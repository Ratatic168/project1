# ПВЗ Склад — система управления складом пункта выдачи

Система управления складом небольшого пункта выдачи заказов (по аналогии с Ozon). Ведёт учёт товаров, заказов и клиентов, управляет приёмкой, размещением и выдачей, а также визуализирует склад в виде 2D-схемы и 3D-модели — с наглядным показом, **где и на какой полке лежит каждый товар**.

## Возможности

- **Дашборд** — оперативная сводка: активные заказы, готовые к выдаче, заполненность склада, распределение по статусам.
- **Заказы** — полный жизненный цикл: `в пути → принят → размещён → готов к выдаче → выдан`, плюс отмена.
- **Визуализация склада**:
  - **2D-схема** (SVG): вид сверху, выбор уровня полки, цветовая индикация заполненности ячеек, клик по ячейке показывает содержимое.
  - **3D-модель** (Three.js): помещение со стеллажами и коробками на полках, вращение/масштабирование мышью, выбор ячейки.
  - **Сквозная навигация**: из карточки заказа можно открыть 2D или 3D с подсветкой именно тех ячеек, где лежит заказ; при выдаче сразу видно стеллаж, полку и ячейку.
- **Товары** — каталог с габаритами, весом, ценой и штрихкодом; добавление новых товаров.
- **Клиенты** — справочник получателей.
- **Поиск** — по штрихкоду, SKU или номеру заказа с указанием, в каких ячейках лежит результат.
- **Журнал операций** — история всех событий склада.

## Стек

| Слой | Технология |
|------|-----------|
| Backend | Node.js 23.6+ (TypeScript без сборщика), Fastify 5 |
| База данных | SQLite через встроенный модуль `node:sqlite` (без нативной компиляции) |
| Frontend | React 18, TypeScript, Vite 5, React Router, Three.js |
| Визуализация | SVG (2D) + Three.js (3D) |

> Нативный TypeScript в Node работает начиная с версии 23.6 (type stripping). Проверено на Node 26.

## Требования

- Node.js **23.6 или новее** (проверено на 26.11)
- npm 9+ (проверено на 11.20)

## Установка и запуск

```bash
# 1. Установить зависимости backend
npm install

# 2. Установить зависимости frontend
npm install --prefix web

# 3. Собрать frontend (в web/dist)
npm run web:build

# 4. Запустить сервер
npm start
```

Сервер поднимется на `http://127.0.0.1:3000`. При первом запуске автоматически создастся демонстрационный склад с данными (если база пустая).

### Отдельные команды

| Команда | Описание |
|---------|----------|
| `npm start` | Запустить сервер (API + раздача собранного фронтенда) |

## Демо-данные

При первом запуске генерируется демонстрационный склад:

- Помещение **10×8 м** с **8 стеллажами** (коды A–H) и **256 ячейками**.
- 15 товаров, 8 клиентов, 24 заказа в разных статусах.
- Товары распределены по всем стеллажам и уровням.

Сбросить к исходному состоянию: `npm run seed`.

## Модель данных

- `racks` — стеллажи (габариты, уровни, ячейки на уровень).
- `locations` — ячейки хранения (адрес вида `A-02-03` = стеллаж A, полка 2, позиция 3).
- `products` — товары (SKU, штрихкод, габариты, вес, цена).
- `customers` — клиенты.
- `orders` — заказы (номер, статус, клиент, сумма).
- `order_items` — позиции заказа (товар, количество, привязка к ячейке).
- `stock` — размещения товаров по ячейкам (что и сколько где лежит).
- `events` — журнал операций.

## REST API

Базовый префикс: `/api`.

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/health` | Проверка работоспособности |
| GET | `/layout` | Планировка склада + ячейки с содержимым (для 2D/3D) |
| GET | `/cells` | Все ячейки |
| GET | `/cells/:id` | Одна ячейка |
| GET | `/products` | Список товаров |
| POST | `/products` | Создать товар |
| GET | `/customers` | Список клиентов |
| POST | `/customers` | Создать клиента |
| GET | `/orders?status=&search=` | Список заказов (с фильтрами) |
| GET | `/orders/:id` | Заказ с позициями |
| POST | `/orders/:id/accept` | Принять на склад |
| POST | `/orders/:id/store` | Разместить в ячейки |
| POST | `/orders/:id/ready` | Готов к выдаче |
| POST | `/orders/:id/issue` | Выдать получателю |
| POST | `/orders/:id/cancel` | Отменить заказ |
| GET | `/dashboard` | Сводка для дашборда |
| GET | `/events` | Журнал операций |
| GET | `/search?q=` | Поиск по штрихкоду/SKU/номеру заказа |
| POST | `/seed` | Сбросить демо-данные |

## Расширение и интеграции в будущем

1. **Переход на PostgreSQL.** Вся работа с БД в `server/service.ts` и `server/db.ts` (слой `node:sqlite`). Замените реализацию доступа к данным, не трогая API и фронтенд.
2. **Подключение к внешней системе (API маркетплейса).** Добавляйте маршруты/вебхуки в `server/server.ts`, вызывая те же функции `service.ts` (acceptOrder/storeOrder/issueOrder).
3. **Штрихкод-сканер.** Ввод штрихкода/номера уже обрабатывается `searchByBarcode` (`GET /api/search`).
4. **Оповещения клиентов (SMS/email).** Вставьте вызов провайдера в `markReady`/`issueOrder` в `server/service.ts` (сейчас там заглушки).
5. **Авторизация/роли.** Добавьте middleware в `server/server.ts` (Fastify hook `onRequest`).

## Проверка работоспособности

При запущенном сервере:

```bash
npm test
```

Тест проверяет все GET-эндпоинты, структуру layout, поиск, полный цикл заказа (приёмка → размещение → готовность → выдача) с контролем списания остатков из ячеек, а также создание товара и клиента.

## Примечания

- Фронтенд собирается в `web/dist` и раздаётся самим сервером.
- В режиме разработки фронтенд (`npm run web:dev`) проксирует `/api` на `http://127.0.0.1:3000`.
- База данных — один файл `data/wms.db`; для сброса удалите его или выполните `npm run seed`.
